# Agent 编队使用指南

简体中文 | [English](agent-fleet-en.md) · [用户手册](user-guide-zh.md) · [README](../README.zh-CN.md)

Agent 编队从本地客户端的结构化日志中只读观测成员、任务、协作关系和用量，提供拓扑、任务、时间线与资源四个视图。

**当前交付状态：** Windows debug 原生构建已实现 R7–R10，主端真实账本、生命周期、恢复和 10 项界面检查通过，Agent Rust 定向回归 94 项、前端回归 19 项通过。R10 独立原生复核 118 项通过，详见“当前验收记录”。安装包及跨平台发布尚未交付。

## 打开工作区

1. 在 XY Switch 桌面程序中，打开品牌旁的工作区菜单，选择 **Agent 编队**。应用内路由是 `#agents`。
2. 首次读取快照时启动本地采集。查看顶部的真实数据源，或进入 **资源**，确认来源连接、采集模式和最近检查时间。
3. 从 **团队** 选择目标团队，或保留 **所有团队**。默认打开 **拓扑**；选择成员、任务、事件或用量分组可打开详情。
4. 使用 **返回配置工作区** 回到离开前的配置页面。

浏览器预览显示 **需要原生桌面程序 / 真实数据未连接**，没有本地日志连接或模拟成员数据。首次导入较多历史日志时，记录会分批出现。

## 按问题选择视图

| 视图 | 操作 | 可以核对的内容 |
| --- | --- | --- |
| 拓扑 | 查找并选择成员，缩放、拖动画布或折叠分支 | 父子关系、派生、具有明确接收者的任务分配或交接；详情中的成员、团队、父成员和证据事件 ID |
| 任务 | 按状态筛选或搜索任务，打开详情，再定位成员 | 回合或委派、执行成员、请求方、起止时间、结果短摘要及归属用量 |
| 时间线 | 按成员、任务和本地起止时间筛选，分批加载事件 | 结构化生命周期、工具调用状态、公开消息短摘要、用量与上下文事件；源时间戳、采集时间、来源相对路径、行号及关联 ID |
| 资源 | 选择数据源查看能力；切换用量维度并打开分组详情 | 来源连接和覆盖说明、累计 Token、用量记录数、费用与计量依据 |

事件详情中的 **在此时刻回放** 可定位历史快照。**查看成员事件**、**查看任务事件** 和 **定位成员** 用于在详情、时间线与拓扑之间跳转。

成员的 `running`、`waiting`、`completed`、`failed`、`interrupted`、`unknown` 状态来自明确的生命周期证据。工具调用失败只描述该次调用。DSH 的 `turn/end` 报告 `completed` 时，该回合完成、成员进入等待；它没有证明成员永久结束。

来源的 `connected`、`disconnected`、`unavailable` 单独表示日志是否可读。来源断开会保留已观测的执行状态；日志静默不会自动推断成员完成、失败或断开。拓扑只展示有结构化证据的关系，无法观察隐藏通信或未记录的内部协作。

## 查看六维用量

在 **资源 → 维度** 中选择分组，再打开某一行查看输入、输出、缓存、推理和费用明细。

| 维度 | 统计对象 | 阅读方式 |
| --- | --- | --- |
| 成员（`agent`） | 一个成员拥有的用量记录 | 查看成员自身消耗；子成员的记录归子成员 |
| 任务（`task`） | 有明确回合、请求或委派归属的记录 | 无法归属的记录不会按名称或耗时分摊给任务 |
| 会话（`session`） | 原生会话 ID | 对照客户端会话记录 |
| 团队（`team`） | 由明确关系连接的成员 | 查看当前所选团队的累计用量 |
| 客户端（`client`） | 来源客户端 | Codex Desktop 与同 schema 的 CLI 由同一 `codex` 适配器归组，不能据此拆出各进程的消耗 |
| 模型（`model`） | 记录中的模型 ID | 查看已报告模型的用量；缺失模型保持未知 |

六种维度是同一批记录的不同分组，不能把六张汇总再相加。数字受团队选择、回放时刻、来源覆盖和历史保留范围影响。任务归属缺失时，任务分组不保证覆盖全部成员用量。

### Token 口径

| 字段 | 含义 |
| --- | --- |
| 输入 | 归一化后的输入，已包含缓存读取和缓存写入 |
| 输出 | 已包含来源报告的推理 Token |
| 缓存读取 / 缓存写入 | 输入的细分子集 |
| 推理 | 输出的细分子集 |
| 总量 | 输入 + 输出 |

例如输入 100、输出 20，其中缓存读取 60、缓存写入 10、推理 8，总量仍为 **120**。缓存与推理不能再次加到总量。没有用量记录时显示 `—`；DSH 协议允许缺省的可选细分计数按适配器口径记为 0，具体见事件的 **用量依据**。

- Codex 优先使用 `token_usage_record`，以全局 `response_id` 去重，并校验 `thread_id` 所有者。已有逐响应记录时，`token_count` 不再额外累加；旧格式使用有基线的累计差分，并提示覆盖或归属缺口。复制的父会话历史不计入子成员的新消耗。
- DSH v4 的原生 `inputTokens` 是未缓存输入；适配器加上 `cacheReadTokens` 和 `cacheWriteTokens` 后统一口径。同一 step/attempt 结算槽的修订按原生 `seq` 替换旧值，明确的新尝试才形成新槽。seeded 会话先定位继承区间边界，避免把继承历史计作新消耗；本次没有真实 seeded 运行样本。

### actual / estimated / unknown 费用

| 口径 | 界面表现 | 含义 |
| --- | --- | --- |
| `actual` | 实际费用 | 仅使用来源明确报告的费用；本次 Codex / DSH 日志没有实际账单，此项未知 |
| `estimated` | 估算费用 | 按完整模型 ID 精确匹配 XY Switch 已保存价格，并具备该记录所需费率时计算；事件详情保留价格来源与版本 |
| `unknown` | 金额为 `—`，并列出费用未知记录数 | 模型、精确价格或必要费率缺失；例如发生缓存写入但没有缓存写入价格 |

估算费用以美元显示。已知记录的估算小计可以与费用未知记录同时存在；此时小计不能代表完整费用。不会按模型名称片段猜价格，未知费用也不会补成 0。实际费用与估算费用分开展示。

本次原生账本报告中，Codex 的 995 条和 DSH 的 362 条用量记录费用均未知，`actualCostUsd`、`estimatedCostUsd` 都为 `null`。原生 UI 已检查费用分类和缺失值展示；这些结果没有提供真实账单或已知估算金额的对账证据。

## 理解最近请求上下文

成员详情的 **上下文** 显示最近一次来源报告的请求输入占用、已报告的窗口大小、**测量于** 和 **测量依据**。Codex 使用最近请求输入，DSH 使用最近已结算请求输入；回放取截止时刻内的最近测量，保留其 `measuredAt` 和 `basis`。它与累计 Token 分开计算。

这里的数值不是实时内存、CPU / 内存采样或模型的隐藏内部状态。客户端尚未写出新测量时，旧测量仍带原时间显示。窗口缺失时显示 **窗口未提供**；没有测量时显示 **没有上下文测量**，不按模型名称推算窗口或补出占用百分比。

## 数据来源与证据覆盖

采集器读取已解析的 Codex 主目录中的 `sessions`、`archived_sessions`，以及 DSH 主目录中的 `sessions`。通常分别位于 `~/.codex` 和 `~/.dsh`；有效的 `CODEX_HOME` / `DSH_HOME` 会影响对应主目录。

| 来源 | 当前实现 | 本次证据 |
| --- | --- | --- |
| Codex Desktop 本机 `0.159.0-alpha.12.1` | JSONL 有界增量采集；明确父线程、协作接收者、回合和逐响应记录 | 本次原生构建的指定历史快照对账一致：44 成员、995 响应、78,811,720 Token；另有真实运行到完成的生命周期证据 |
| Codex CLI 同 schema 日志 | 复用 Codex 适配器，按实际结构化字段解析 | 本次没有独立 CLI 进程运行证据，Desktop 证据不扩展为 CLI 实测通过 |
| Codex `archived_sessions` | 历史读取，保留日志已有关系与事件 | 作为历史来源展示，不代表当前进程仍在运行 |
| DSH v4 plain JSONL | 有界增量读取；头部 `parentSession`、`turn/start`、`turn/end`；step/attempt 用量 | 已核对实现与字段契约；本次没有独立 plain 在线运行证据 |
| DSH v4 `session.v4.jsonl.zstd` | 有界解压历史导入，逐完整帧验证；文件变化后继续读取 | 本次原生构建已通过真实父子历史样本对账：2 个源会话、362 个结算槽、101,738,633 Token；此前该样本的大行导入阻塞已解除 |

普通日志为 `delayed`（延迟采集），归档和压缩日志为 `history`（仅历史）。源详情逐项列出能力与限制。当前 DSH 适配器只接受已核对的 v4；experimental Team v2 通信没有接入。其他客户端没有对应观测适配器时，不能从普通正文推断成员或协作关系。

## 刷新、回放与保留

- **采集节奏：** 本地增量检查约每 **2 秒**一次，约每 **15 秒**发现新文件，另有客户端写入延迟。每轮文件数、读取字节数和事件数都有上限，积压分批推进；这不是固定 2 秒内可见的保证。
- **界面刷新：** 原生事件通知触发快照刷新，另有 **30 秒**低频校准。**刷新** 请求已采集的快照，不会强制客户端写出日志。界面的“实时观测”表示跟随最新已采集事件，实际来源模式仍以 `delayed` / `history` 为准。
- **压缩历史：** zstd 按验证完成的帧导入，半帧或半行等待补齐，受读取预算和解码窗口限制。查看源详情中的分批读取、覆盖不完整或解析诊断。
- **历史回放：** 打开 **历史回放**，选择本地时间或拖动时间轴，可播放、暂停并切换 1× / 10× / 60×。每帧由后端按保留事件重建；来源连接与最近检查仍表示当前采集状态。使用 **返回实时** 跟随新事件。
- **回放与日期筛选（R7）：** 事件查询的顶层 `scope.at` 单独确定团队成员关系截止点：回放传原始 `replayAt`，实时传 `{ at: null }`。`query.since` / `query.until` 只筛选事件日期；回放时事件上界为 `min(until, at)`，未填 `until` 时为 `at`。更改回放时刻或筛选条件会重新分页。旧调用省略整个 `scope` 时仍以 `until` 作为关系截止点，不能用该兼容方式表达独立日期筛选。
- **保留范围：** 默认保留 **30 日**，本地观测库全局最多 **200000 条规范化事件记录**。清理依据事件源时间戳；新导入的旧日志也可能超出保留期。时间或条数上限都会缩短可回放范围。页脚 **观测说明** 显示保留天数、可用历史和截断提示。清理只影响 XY Switch 的派生观测记录，客户端原始文件不受影响。

## 只读与凭据脱敏

Agent 编队只读取客户端日志；没有创建、停止、控制 Agent 或发送任务消息的操作。观测模块复用 XY Switch 的本地 SQLite、Tauri IPC 和模型价格表。

日志在采集时解析，持久化内容限定为白名单元数据、计数和短摘要。摘要与可显示字段会经过凭据脱敏，包括令牌、密码、授权信息及 URL 中的凭据信息；完整提示词、工具参数/输出和推理正文不作为观测事件保存。公开消息短摘要与隐藏推理、隐藏通信有明确的可见性边界；后两者不可观察。

## 排查缺失或不一致的数据

| 现象 | 检查位置与处理 |
| --- | --- |
| 需要原生桌面程序 | 在 XY Switch 桌面程序中打开 `#agents`；浏览器预览没有本地观测源 |
| 数据源不可用或没有成员 | 查看 **资源 → 数据源** 的目录可读性、文件数、模式和诊断；等待发现与分批导入，再检查团队和历史时刻 |
| 来源断开，成员仍显示原状态 | 恢复来源可读性，查看最近检查；状态需后续生命周期事件更新 |
| 显示上次快照或通知连接中断 | 查看最后成功读取时间及所显示范围，使用 **重试 / 刷新**；通知通道有低频校准 |
| Token 与另一处统计不同 | 对齐团队、原生会话、时间截点、保留范围和用量依据；核对逐响应去重、继承历史、结算修订及未知任务归属 |
| 费用或上下文显示 `—` | 查看精确模型价格、费用未知记录、测量时间和窗口是否报告；这些空值不代表零消耗 |
| 缺少父子关系或协作连线 | 检查来源是否有明确父会话或接收者 ID；名称、正文与同一工作目录不足以建立关系 |

## 验收与已知限制

此前 Windows 隔离原生验收覆盖来源账本核对、明确父子关系、事件与生命周期时间顺序、来源断开重连、重启恢复、六维资源统计和响应式界面。原始来源记录与个人运行统计保留在本地证据归档。当前全量测试结果及本次原生验收范围见 [1.3.0 发布验收](channel-groups-acceptance-1.3.0.md)。

已有持久化生命周期时间戳不会自动迁移。因旧版 `sequence_gap` 停止的游标，也不会只因提高单行大小限制就重读未变化的文件。此前 R10 验收使用新的隔离观测数据库，现有观测数据库的自动修复尚未验证。

独立 Codex CLI 进程、真实 DSH 普通 JSONL 任务、真实 seeded-run 样本、DSH Team v2、隐藏状态、实际账单和跨平台 Agent 执行仍未验收。缺失费用继续保持未知。
