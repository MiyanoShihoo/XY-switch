# 原生验收补充（2026-10-30）

## 目标和边界

本轮补足两个旧证据缺口，不更改已发布的 1.2.0：

- Windows 开发版的真实文件选择器 → 实际 WebView UI → Rust 加密文件 → 逐项导入 → 备份与回滚。
- iOS 模拟器应用从加载状态进入可用页面，以及真实偏好写入、进程重启后的持久化和移动端同步只读界面。

加密同步没有进入 1.2.0。本轮测试使用独立 feature CI **40908795739 / attempt 1** 的产物，源码为 `614e2b21ea59b7256d09c7f34b30f6aeecd9064c`；验收脚本提交与被测应用源码分别记录。复用旧二进制前，CI 必须确认应用源码、Tauri 配置、前端资源、依赖与版本没有变化，并校验 GitHub artifact ZIP 摘要、包内清单与安装后的 EXE 摘要。

## 验收机制

### Windows

只在一次性 GitHub-hosted Windows runner 上运行，拒绝预先存在的应用数据库。安装来源已验证的 NSIS 包；CDP 只通过测试子进程环境开启并限定 loopback，不修改应用源码、安装包或用户级配置。

- 使用真实生产 IPC 构造合成供应商、收藏和自定义价格；不设置、读取或测试真实供应商密钥，不调用付费接口。
- 导出、导入、取消及回滚使用实际 UI。另一个进程通过 Windows UI Automation 操作属于被测 PID 的 `#32770` 原生文件对话框，保存控件树和截图；不替换 IPC 或文件选择器。
- Node 独立解密实际保存的 `.xysync`，验证 AES-256-GCM / PBKDF2 参数、白名单、同步身份隔离、错误口令与 tag 篡改拒绝。
- 验证取消与错误口令不写入；正确预览不应用配置；每项必须选定，分别覆盖接受与保留本地。
- 验证同目标合并保留本机 advanced，变更目标保留原供应商并创建新禁用副本；验证备份和回滚。同步新增副本在回滚后仍保留为禁用，这是产品约定。
- 口令随机生成且不持久化；检查输入框、WebView 存储与 SQLite 文件。测试后结束被测进程并卸载，独立检查 SQLite 完整性。

这不是 Linux/macOS 原生 UI 结果，也不是 MSI 专项同步验收。此前三个桌面平台的真实后端测试和安装包测试仍作为独立证据。

### iOS

旧脚本遇到任何非空内容就提前退出，加载页也能通过。这证明旧判据不足，不能仅凭那张截图诊断为永久初始化故障。

新脚本在新建模拟器中安装来源已验证的应用，通过独立 XCTest runner 操作原安装包，不重编译或注入被测应用：

1. 等待种子供应商实际可见且加载状态结束。
2. 进入设置，等待真实偏好读取完成。
3. 通过 UI 修改请求超时至 175 秒并保存。
4. 检查移动端加密同步只读，不出现导出动作。
5. 终止、重新启动应用，检查偏好仍为 175 秒。
6. 从该模拟器的应用容器只读检查 SQLite 和已保存的值。

必须同时有成功且未跳过的 XCTest、数据库回读与非空最终画面才算通过。保留 `.xcresult`、可访问性树、截图、Xcode 版本和选择的运行时；加载截图本身不再决定通过。此项不覆盖签名 IPA 或 iPhone/iPad 真机。
