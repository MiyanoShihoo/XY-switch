## 2. 下一阶段任务

### P0：单任务总尝试与费用控制

1. 在现有每次发送前预留、精确价格和静态拒绝原因基础上，为同一逻辑任务建立总尝试及总费用上限。
2. 合并统计应用重试、故障转移和客户端重试叠加，确保每次物理发送都有可追溯归属。
3. 对取消后的停止派发、超时、缺失 usage 和未知费用状态补齐生产代理回归。
4. 验证本地配额拒绝不会增加上游调用、账本预留或供应商失败计数。

验收标准：故障、并发和取消场景下，任务总发送及费用预留不越过配置上限；诊断能解释每次尝试或阻断。

### P0：安装包与插件业务验收

1. 用同一提交构建安装包，绑定源码、包摘要和平台任务结果。
2. 在隔离数据目录验证 GUI、应用接管、凭据读取、冷启动、停止及恢复。
3. 为实际使用的插件分别完成一项代表性业务，记录调用、结果及失败归因。
4. 按平台分别验证安装、升级、卸载和配置恢复，明确已证实的环境范围。

验收标准：可分发包的实际行为与源码回归一致，记录可复现且敏感信息不会进入公开报告。
