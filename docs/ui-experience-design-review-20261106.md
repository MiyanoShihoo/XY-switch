# XY Switch 独立产品设计审查

日期：2026-11-06。审查对象：方案第1–10节及 before 清单中的22张真实 renderer 截图；同时采纳用户最后补充的导航实测校正。本轮只写入此评审文档。

## 结论：否决当前提交版本（veto）

否决的是当前版本的整体放行。单层直达目录、会话目录与阅读分离、市场结果与候选详情对照、用量贡献下钻请求，具有真实的结构收益，可以沿用。当前仍有部分收益与现状重合，以及恢复和切换的必要上下文没有明确落实到操作位置；布局预算也需要成为确定的实施约束。

以下仅4项问题，均给出已有方向内的最小修正。不要求重新研究、另找风格或再做A/B。主Agent落实修正后处理UI解冻；本次方案审查到此结束，后续我保持独立身份，仅审实际renderer截图。

### 1. 部分页面把已有能力计作重构收益，意义不足

**证据：**第9节称供应商可直接比较/显式切换，账号用途分开且查状态不必进管理弹窗，插件在包上下文管理版本与授权，提示词复制/编辑位于正文前。providers截图已有全宽比较表及独立“设为当前”；accounts已有网关/原生分区、状态和额度；plugins已有包目录、版本、客户端授权、权限签名与版本历史；prompts的“复制内容”“编辑”已经位于正文前。这些不能重复计作新增改善。

**影响：**以这些表述验收，局部移动和改名也可能被认定完成了结构重构。总览新增候选比较后，供应商页再增加当前摘要，还可能重复呈现同一组信息。

**最小修正：**在原有选择中明确保留项与真实增量。账号的增量应落在供应商、实际策略与账号的对应关系；插件明确尚未连通的版本、授权、调用路径；总览服务当前环境选择，供应商目录服务跨配置管理。提示词若没有新的结构阻碍，应如实保留现状，不把已有顶部动作列为新增成果。

**通过条件：**每个声称重构的页面，用同内容前后截图及明确路径说明一个实际改变的决策关系。仅改按钮、边距或颜色不计；已存在的能力不计。账号策略与对应供应商、账号可同时辨认；重复当前摘要不得挤掉候选协议、模型、地址和测试来源。此项阻断以现有收益表述整体放行。

### 2. 会话恢复的完整工作目录需要明确保留在恢复操作附近

**证据：**两张sessions-reader截图在选中目录项显示 `D:/Projects/xy-switch`，目录底部还显示恢复前切换工作目录的提示。第8节阅读草图移除会话目录，顶栏只示意“项目 xy-switch”，文字仅承诺恢复前目录提示“仍可得到”。第4节虽保留项目/恢复上下文，但尚未明确完整目录在阅读态的可见位置。

**影响：**只显示短项目名，无法区分不同父目录下的同名项目。若把恢复前提与来源管理一起弱化，复制命令前就需要额外寻找必要信息。这里是方案的可见性缺口，不是已经确认实现丢失了路径。

**最小修正：**恢复区域同时保留客户端、可完整核对的工作目录及先切换目录的提示。长路径可独占一行并展开完整值；来源日志、完整会话ID和删除继续留在管理区。

**通过条件：**以两个同名但路径不同的项目检查阅读态。在1024及320宽度，复制前能核对完整目录和客户端，提示不藏在来源/管理中；长路径不遮住返回、查找和恢复操作，正文仍满足方案自身约250px内开始的目标。逐字复制且不执行由实现方验证。此项须在解冻前明确到结构中。

### 3. 总览单客户端摘要没有明确承载激活的多目标影响范围

**证据：**overview截图分别展示客户端Codex、当前供应商Orion、本地路由已停止、Claude/Codex/Gemini路由目标及历史测试。第4节拟以当前客户端/供应商/模型摘要承接直接切换；第10节明确，有接管时激活会同步所有已接管目标。执行范围已有契约，但方案未明确点击前在哪里展示该范围。

**影响：**用户可能把动作理解成仅为摘要中的客户端切换配置。busy/testing/current/enabled限制及正确结果反馈解决执行问题，仍需要与点击前的影响说明配合。

**最小修正：**在“设为当前”所在工作区显示影响所有已接管目标的事实及可核对的目标范围；无接管时明确只更改当前配置。配置选择、实际运行、接管范围、历史测试分别表达；沿用原有确认，不额外增加无意义确认步骤。

**通过条件：**实施后提供无接管、多目标接管、切换后状态读取失败三个renderer状态。点击前范围清楚；部分结果不被统一成功提示覆盖；历史测试不成为实时健康标识。明确点击及状态锁沿用第10节，不能选行激活、不能await后无条件报成功。此项须在解冻前明确到结构中。

### 4. 新导航挤占宽度后，多栏工作区仍缺确定的净宽及重排规则

**证据：**第3/8节规定导航184–196px、低于960才抽屉化，同时1024阅读态安排约170px讨论栏。按196px导航计算，`1024 - 196 - 170 = 658px`，这还未扣页面边距、栏间距和正文内边距。该预算并非已经算不通，但“剩余正文／空间不足时收起”无法确定何时收拢。marketplace-1024现状首个候选已经较低；usage-1024明暗两图均有趋势横向滚动，贡献行位于首屏以下。

**影响：**新增导航宽度可能削弱阅读、候选对照和请求证据的有效空间。全局导航变成抽屉，也不能自动证明MCP矩阵、编辑章节、审核内容在320宽度可达。

**最小修正：**为现有多栏方案补净宽分配、最小可用正文和确定的收拢条件。讨论目录依据正文空间收起；市场/请求详情改为单页时保留筛选、分页、选择和返回位置；MCP重排保留服务与客户端对应关系。审核的风险摘要、关闭、底部确认需明确限高和滚动归属。

**通过条件：**实施后核验1024×768、1280×800、1440×960及820/390/320。会话达到正文位置目标；市场切换候选保留结果上下文；六个趋势点与单位可直接比较，贡献入口不被扩大后的图表挤出主要工作区；关键说明和确认不被固定栏覆盖。除确需二维表达的局部表格/代码外，不依靠整页横向滚动维持布局。明暗采用同一语言、结构、密度和状态语义。此项是待证明的适配约束，不宣称未见的小屏已经存在具体故障。

## 导航校正与已接受方向

旧活动分组会记忆最近页：跨组到最近页可以1次，到该组非最近页才需2次。用户实测“用量→工具/最近市场→提示词”为2次，并记录于workflow-baseline.json；本次采纳该补充，没有另行运行路径。

因此，新导航的主要收益是14个目的页直接可见、去向可预期，以及前往组内非最近页时省去组选择；不声称旧导航一律需要2次。184–196px目录与内容空间的取舍仍须满足第4项。静态分类不能再变成点击层级。

会话空阅读面板、市场详情遮住候选、用量贡献缺少连续请求路径，均有现状证据，已选方向可沿用。客户端按configOwner组织共享归属、MCP挂载矩阵、Skills把查找与来源维护分开，以及设置/治理按任务进入，也有任务依据。

第10节的凭据保留/替换/删除、客户端共享范围、权限增量与全集、精确版本与指纹、一次性授权、预算口径、危险确认及过期清理均接受并保留。完整契约不等于已经证明风险信息在界面可见。

## 2026-11-06 四项修订复核：设计阶段通过，允许实施

本次仅复核方案第11节及第4/8/9节对应修订。原审查与22张before截图记录保留。本结论解除原四项对当前修订方案的实施阻断；允许进入实施，不代表改版UI已经完成或通过实际效果验收。

- 原第1项（真实增量）：通过。第9节及11.4区分已有能力与新增关系、工作区和返回路径；总览负责当前环境选择，供应商目录负责跨配置管理，不以重复摘要或已有顶部按钮计作改善。
- 原第2项（恢复上下文）：通过。第8节及11.2将客户端、默认完整可见的工作目录、先切换提示放在恢复操作附近；无路径明确说明，320长路径自然增高，约250px正文目标限定于1024及以上常规内容。
- 原第3项（切换范围）：通过。第4节及11.1仅按loadAppTakeovers/list_app_takeovers返回的AppTakeoverStatus.active确认实际范围；不以routeTargets推断接管，未知或失败先刷新并禁用激活，不冒充空集合。明确多目标影响，并保留显式激活、控制器限制及部分成功结果。
- 原第4项（净宽与收拢）：通过。第11.3六档页面净宽计算闭合；940/960/1100阈值明确按页面容器净宽判断，1024采用全宽正文和独立详情。返回筛选、页码、选中项、滚动及焦点、跨断点保留、审核限高与滚动归属均已明确。

**剩余条件仅留待实施后验收：**沿用原四项的同内容前后截图与任务路径要求，覆盖三档桌面及820/390/320宽、同语言明暗、同名异路径恢复、无接管/多目标/范围未知或失败/切换后刷新失败，以及长权限审核的可读性与操作可达性。控制器保护、复制不执行、凭据与票据生命周期等行为由实现方验证，不能以截图替代。本独立审查者后续仅审实际renderer截图，最终是否完成届时另定；本次无需等待实现。
